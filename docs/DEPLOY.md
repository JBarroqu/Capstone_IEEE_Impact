# Deploying on the internet

Two ways: **Render** (what the team uses, `render.yaml`) or **your own server** (`docker-compose.public.yml` with Caddy). Both put the pages and the API on one https origin, so cookies are first-party and no CORS is needed.

## Render

```
Browser ──https──> Render proxy ──> wish-app (Next.js, public) ──/api/* rewrite, private network──> wish-api (FastAPI, private)
                                                                                                        └──> wish-db (Render Postgres)
```

Render does https and certificates. The API is a **private service** with no public URL; the browser calls `https://wish-app.onrender.com/api/...` and Next forwards it. One origin matters on Render: `onrender.com` is a public suffix, so `wish-app.onrender.com` and `wish-api.onrender.com` would be different sites and the cookies would break (Safari blocks them outright).

### First deploy

1. In the Render dashboard: **New > Blueprint**, connect GitHub, pick `JBarroqu/Capstone_IEEE_Impact` and the **`wish-engine`** branch. Render reads `render.yaml`.
2. It asks for the secrets marked `sync: false`:
   - `ADMIN_PASSWORD`: 8+ characters, not `change-me` (admin login is refused otherwise). Use a long random one.
   - `GEMINI_API_KEY`: a paid-tier key for real participants.
   - `OPENROUTER_API_KEY`: optional backup models; leave empty to skip.
   `SESSION_SECRET` is generated by Render. `DATABASE_URL` and the API's private address are filled in by the Blueprint.
3. Apply. Render creates `wish-db`, then builds `wish-api` (it creates the tables on start) and `wish-app`. The first build takes several minutes.
4. Open `https://wish-app.onrender.com` (the exact URL is on the wish-app page), do a dry run as `TEST <name>`, open `/admin`, then delete the test session there.
5. Check the client IP the rate limits see: logged in to admin, open `/api/admin/client-ip`, then again with a fake header (`curl -H "X-Forwarded-For: 1.2.3.4" -b "wish_admin=<cookie>" https://.../api/admin/client-ip`). `ip` must be your real address both times. If it shows Render's internal address instead, set `PROXY_HOPS=2` on wish-api.

Every push to `wish-engine` redeploys both services (auto-deploy). Env vars are edited on each service's Environment page; `sync: false` values are only asked for once.

### Cost and plans

`render.yaml` uses the smallest paid plans: wish-app and wish-api `0.5c-512mb`, wish-db `0.1c-256mb`. Private services have no free plan. To save money, wish-app can be `free`, but it sleeps after 15 minutes idle and the first student then waits about a minute. A `free` database expires after 30 days. Check current prices on Render before applying.

### Render notes

- **Backups:** paid Render Postgres has daily backups (dashboard > wish-db > Recovery). Export the CSVs from `/admin` after each study session anyway.
- **One API instance only.** Keep wish-api at 1 instance: rate limits and model health are in memory.
- **Logs:** each service's Logs tab. Model failures show as `options failed` / `classify failed` in wish-api.
- **Custom domain:** add it on wish-app only (Settings > Custom Domains); nothing else changes.

## Your own server (Caddy)

`docker-compose.public.yml` runs the whole app on one server behind Caddy, on one https domain. It is a separate stack from the local `docker-compose.yml` (its own project name, so its own database).

```
Browser ──https──> Caddy (:443, :80 redirects) ──/api/*──> api (FastAPI, 1 worker)
                                               └──else───> app (Next.js)       both ──> db (Postgres, not published)
```

Only Caddy is published. Pages and API share the origin `https://DOMAIN`, so there is no CORS and the cookies are first-party.

### What you need

- A Linux server with Docker (any small VPS: 1 vCPU, 1–2 GB RAM is enough), ports 80 and 443 open.
- A domain or subdomain with a DNS `A` record pointing at the server (`wish.example.com`). Caddy gets and renews a Let's Encrypt certificate on first start; that needs the DNS record and port 80 reachable.
- A Gemini API key on a **paid** tier for real traffic (see "Before real participants").

### Steps

1. Copy the repo to the server and create `.env` from `.env.example`. Set at least:
   ```
   DOMAIN=wish.example.com
   POSTGRES_PASSWORD=<long random string>        # openssl rand -hex 24
   ADMIN_PASSWORD=<8+ characters, not change-me>
   SESSION_SECRET=<long random string>           # optional; default is a random key kept in the database
   GEMINI_API_KEY=...
   ```
   `DATABASE_URL`, `PUBLIC_MODE`, `TRUST_PROXY` and `CORS_ORIGINS` are set by the compose file.
2. Start it:
   ```
   docker compose -f docker-compose.public.yml up -d --build
   docker compose -f docker-compose.public.yml logs -f proxy api   # certificate and API logs
   ```
3. Open `https://DOMAIN`, do a dry run as `TEST <name>`, check `https://DOMAIN/admin`, then delete the test session from the admin page.

Updates: `git pull`, then the same `up -d --build`. Stop: `docker compose -f docker-compose.public.yml down` (data stays in its volume). Backups: `docker compose -f docker-compose.public.yml exec -T db pg_dump -U wish wish_engine | gzip > backup.sql.gz`.

**Trial run on a laptop:** `DOMAIN=localhost POSTGRES_PASSWORD=anything docker compose -f docker-compose.public.yml up -d --build`, then `https://localhost` (Caddy's own certificate; accept the warning) and `BASE_URL=https://localhost npx tsx scripts/e2e.ts`. Remove it with `... down -v`.

## What public mode turns on

| Piece | Where |
|---|---|
| Signed session cookie: `/api/session` (after consent) sets it; options, classify, questions, wish and events refuse requests without it (401) or with a body `sessionId` that does not match. A wish can only be changed by the session that created it. | `backend/wish_api/security.py`, `routes/student.py`; the client waits for it (`lib/client-api.ts` `whenSessionReady`, `lib/track.ts` `setReady`) |
| Rate limits per IP, per session and global, `429` with `Retry-After` | `backend/wish_api/rate_limit.py` |
| Real client IP: the API reads the rightmost `X-Forwarded-For` entry added by the proxy (`PROXY_HOPS` from the right; client-sent entries to the left are ignored), only with `TRUST_PROXY` | `security.py` `client_ip`; check with `/api/admin/client-ip` |
| HTTPS everywhere, http redirected, HSTS | Render or Caddy; HSTS also from `next.config.mjs` and the API in `PUBLIC_MODE` |
| Signed admin cookie: HMAC, 12 h server-side expiry, `SameSite=Strict`, signs everyone out when the password changes; login refused with an empty, `change-me` or short password, and over plain http from another machine | `backend/wish_api/admin_auth.py`, `routes/admin.py` |
| Body caps: 128 KB at Caddy, 1–64 KB per route in the API | `Caddyfile.public`, `routes/common.py` `read_json` |
| Security headers (CSP `frame-ancestors 'none'`, `X-Frame-Options`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`), no `X-Powered-By` | `next.config.mjs`, `backend/wish_api/main.py` |
| API docs pages (`/docs`, `/openapi.json`) off | `main.py` (`PUBLIC_MODE`) |
| Database not reachable from outside | Render: `ipAllowList: []`; own server: not published, password from `.env` |

The cookie checks, rate limits, body caps and headers are also on in the local stack; HTTPS, HSTS, trusted forwarding headers and the docs switch-off are public-mode only. The 128 KB proxy body cap exists only with Caddy; on Render the API's own caps apply. Limits and their reasons: `docs/SECURITY.md`.
